Trong một câu

Vitest là công cụ chạy test cho dự án JavaScript và TypeScript: nó tìm các file test, chạy từng bài, rồi báo bài nào qua, bài nào hỏng và hỏng ở đâu.

Nếu bài trước nói test là "máy chấm bài", thì Vitest chính là cái máy đó: bạn viết đáp án bằng expect, Vitest chấm mỗi lần bạn lưu file.

Vì sao dùng Vitest

Bạn có thể tự viết if (kq !== 1200000) console.log('sai'), nhưng sẽ nhanh chóng cần: gom test thành nhóm, báo lỗi dễ đọc ("mong đợi 1.200.000, nhận 1.000.000"), chạy lại khi sửa file, giả lập thời gian, đo độ phủ. Vitest có sẵn tất cả, chạy thẳng TypeScript không cần cấu hình thêm, và dùng cú pháp giống Jest nên tài liệu, ví dụ trên mạng đều dùng được.

Từ khoá cần biết

test / it
Một bài test. Hai tên giống hệt nhau.
describe
Gom các test liên quan thành một nhóm.
expect
Bắt đầu một khẳng định về một giá trị.
Matcher
Phần sau expect(x) nói điều cần đúng: toBe, toEqual, toThrow…
Hook (beforeEach…)
Đoạn code chạy trước hoặc sau mỗi test, để chuẩn bị và dọn dẹp.
Mock
Hàm giả thay cho hàm thật, để test không gửi tin nhắn hay gọi mạng thật.
Spy
Theo dõi một hàm có được gọi không, gọi mấy lần, với tham số gì.
Coverage
Tỉ lệ dòng code đã được chạy qua khi test. Chỉ ra chỗ chưa có test, không nói test có tốt hay không.

Vitest chạy một file test thế nào

  1. Tìm file có tên *.test.ts hoặc *.spec.ts.
  2. Đọc các khối describe và test để biết có những bài nào.
  3. Chạy từng test: hook beforeEach, thân test, hook afterEach.
  4. Một expect sai thì test đó dừng và đỏ, các test khác vẫn chạy.
  5. In báo cáo: số test qua, số test hỏng, và với mỗi test hỏng là mong đợi gì, nhận được gì.

Cài đặt và chạy

npm install -D vitest
# package.json → "scripts": { "test": "vitest", "test:run": "vitest run" }

npx vitest          # chế độ theo dõi: sửa file là chạy lại
npx vitest run      # chạy một lần rồi thoát, dùng cho CI
npx vitest run hoc-phi   # chỉ chạy file có tên chứa "hoc-phi"

Vitest 5 cần Node từ 22.12 trở lên. Nó tự tìm các file có .test. hoặc .spec. trong tên. Vitest hiểu TypeScript sẵn, không cần cấu hình thêm cho API sách.

Năm khối cơ bản

import { describe, test, expect, beforeEach, vi } from 'vitest';

describe('tinhHocPhi', () => {          // nhóm các test liên quan
  beforeEach(() => { /* chạy trước MỖI test trong nhóm */ });

  test('8 buổi × 150.000đ', () => {     // một test
    expect(tinhHocPhi(8, 150_000)).toBe(1_200_000);   // một khẳng định
  });
});
  • test (hoặc it, giống hệt nhau): một trường hợp kiểm tra.
  • describe: gom test thành nhóm. Kết quả in ra lồng theo nhóm, dễ đọc.
  • expect(x) rồi tới một matcher như toBe: khẳng định về x.
  • beforeEach / afterEach: chạy trước và sau mỗi test. beforeAll / afterAll: một lần cho cả nhóm.
  • vi: hộp đồ nghề để giả lập (mock), theo dõi (spy) và điều khiển thời gian.

Matcher hay dùng

MatcherKiểm traVí dụ
toBeBằng nhau tuyệt đối (Object.is). Dùng cho số, chuỗi, booleanexpect(res.status).toBe(201)
toEqualBằng nhau theo nội dung, so từng trường. Dùng cho object, mảngexpect(body.tags).toEqual(['thiếu nhi'])
toMatchObjectObject chứa ít nhất các trường nàyexpect(body).toMatchObject({ title: 'Dế Mèn' })
toThrowHàm ném lỗi (truyền vào một hàm, không phải kết quả)expect(() => f(-1)).toThrow(RangeError)
toHaveLengthĐộ dài mảng hoặc chuỗiexpect(list.data).toHaveLength(2)
expect.any(String)Giá trị bất kỳ thuộc kiểu này, dùng bên trong toEqual{ id: expect.any(String) }
.notĐảo ngượcexpect(text).not.toContain('at ')

Phân biệt toBe và toEqual là câu hỏi phỏng vấn kinh điển: expect({ a: 1 }).toEqual({ a: 1 }) qua, nhưng expect({ a: 1 }).toBe({ a: 1 }) hỏng, vì đó là hai object khác nhau trong bộ nhớ.

Làm thử: test hàm tính học phí (bài của Thứ Ba)

// src/hoc-phi.ts
export function tinhHocPhi(soBuoi: number, giaMoiBuoi: number, giamGiaPhanTram = 0): number {
  if (!Number.isInteger(soBuoi) || soBuoi < 0) throw new RangeError('Số buổi phải là số nguyên không âm');
  if (giamGiaPhanTram < 0 || giamGiaPhanTram > 100) throw new RangeError('Giảm giá phải từ 0 đến 100');
  return Math.round((soBuoi * giaMoiBuoi * (100 - giamGiaPhanTram)) / 100);
}

Tự viết 6 test trước khi xem gợi ý bên dưới. Gợi ý: một trường hợp thường, ba trường hợp gom bằng test.each, một ranh giới 0 buổi, và hai đường lỗi.

test.each([
  { soBuoi: 0, gia: 150_000, giam: 0, ketQua: 0 },
  { soBuoi: 8, gia: 150_000, giam: 10, ketQua: 1_080_000 },
  { soBuoi: 3, gia: 99_999, giam: 15, ketQua: 254_997 },   // làm tròn: 254.997,45 → 254.997
])('$soBuoi buổi × $gia, giảm $giam% → $ketQua', ({ soBuoi, gia, giam, ketQua }) => {
  expect(tinhHocPhi(soBuoi, gia, giam)).toBe(ketQua);
});

test('số buổi âm thì ném RangeError', () => {
  expect(() => tinhHocPhi(-1, 150_000)).toThrow(RangeError);
});

test.each chạy cùng một test với nhiều bộ dữ liệu. Mỗi bộ hiện thành một dòng riêng trong kết quả, với tên được điền từ $soBuoi, $gia...

Test code async

Hàm test có thể là async. Vitest sẽ chờ promise của nó. Quên await trước một promise là lỗi hay gặp nhất: test kết thúc trước khi promise xong, và có thể qua dù code sai.

test('tạo sách trả 201', async () => {
  const res = await app.request('/books', { method: 'POST', body: '...' });  // nhớ await
  expect(res.status).toBe(201);
});

// Kiểm tra một promise bị reject
await expect(loadStudent('')).rejects.toThrow('Thiếu id');

Mock, spy và giả lập thời gian

Mock là một hàm giả đứng thay cho hàm thật, ghi lại mình bị gọi bao nhiêu lần, với tham số gì. Dùng khi hàm thật đi ra ngoài (gửi Zalo, gọi ngân hàng) hoặc chậm.

const guiNhac = vi.fn((sdt: string) => `đã gửi ${sdt}`);
['0901', '0902'].forEach((s) => guiNhac(s));
expect(guiNhac).toHaveBeenCalledTimes(2);
expect(guiNhac).toHaveBeenLastCalledWith('0902');

Spy theo dõi một hàm có sẵn, và có thể thay tạm cách nó chạy. Ví dụ tắt console.error trong test nhánh 500 cho kết quả gọn, mà vẫn kiểm tra được là có log:

const spy = vi.spyOn(console, 'error').mockImplementation(() => {});
const res = await app.request('/__boom');
expect(res.status).toBe(500);
expect(spy).toHaveBeenCalledOnce();
spy.mockRestore();   // trả lại console.error thật

Giả lập thời gian cho phép test việc "nhắc nợ sau 3 ngày" mà không phải chờ 3 ngày:

vi.useFakeTimers();
const nhac = vi.fn();
setTimeout(nhac, 3 * 24 * 60 * 60 * 1000);
vi.advanceTimersByTime(2 * 24 * 60 * 60 * 1000);
expect(nhac).not.toHaveBeenCalled();
vi.advanceTimersByTime(24 * 60 * 60 * 1000);
expect(nhac).toHaveBeenCalledOnce();
vi.useRealTimers();

Độ phủ code (coverage)

npm install -D @vitest/coverage-v8
npx vitest run --coverage

Báo cáo cho biết phần trăm dòng, nhánh và hàm đã được chạy qua, kèm số dòng chưa được chạy. Dùng nó như bản đồ để tìm chỗ chưa test, không phải như điểm số để khoe.

Bút đỏ: những câu nghe đúng mà sai

"expect(obj).toBe({ a: 1 }) để so object."Sai. toBe so địa chỉ trong bộ nhớ. Object thì dùng toEqual.

"expect(f(-1)).toThrow() để kiểm tra lỗi."Sai. f(-1) ném lỗi ngay trước khi expect kịp bắt. Phải bọc trong hàm: expect(() => f(-1)).toThrow().

"Mock càng nhiều càng tốt cho test nhanh."Không. Mock quá nhiều thì bạn chỉ test được các mock. Chỉ mock những gì đi ra ngoài hoặc không kiểm soát được.

Tự kiểm tra

Tự trả lời trước, rồi mới bấm mở đáp án.

expect({ a: 1 }).toBe({ a: 1 }) qua hay hỏng? Vì sao?

Hỏng. toBe so cùng một object trong bộ nhớ; hai object khác nhau dù cùng nội dung. Dùng toEqual.

Test một hàm gửi tin nhắn cho phụ huynh mà không muốn gửi thật. Dùng gì?

Một mock (vi.fn()) thay cho hàm gửi, rồi kiểm tra nó được gọi đúng số lần với đúng số điện thoại.

Coverage 100% có nghĩa là không còn bug không?

Không. Coverage chỉ nói dòng nào đã chạy qua, không nói kết quả có được kiểm tra đúng hay không.

Câu hỏi phỏng vấn

toBe và toEqual khác nhau thế nào?

toBe so bằng Object.is, tức cùng một giá trị nguyên thuỷ hoặc cùng một object trong bộ nhớ. toEqual so nội dung từng trường một cách đệ quy. Với số và chuỗi dùng toBe, với object và mảng dùng toEqual.

Mock và spy khác gì? Khi nào dùng?

Mock là hàm giả hoàn toàn thay cho phụ thuộc thật. Spy bọc quanh một hàm có sẵn để ghi lại lời gọi, và có thể giữ hoặc thay cách nó chạy. Dùng khi phụ thuộc đi ra ngoài (mạng, email, thanh toán), chậm, hoặc không xác định như thời gian. Tránh mock chính thứ mình đang test.

Làm sao test một hàm dùng setTimeout hoặc Date.now()?

Dùng fake timers: vi.useFakeTimers() rồi vi.advanceTimersByTime() để tua thời gian, hoặc vi.setSystemTime() để cố định ngày giờ. Nhớ vi.useRealTimers() sau test. Như vậy test nhanh và không phụ thuộc giờ thật.

Test async qua dù code sai. Nguyên nhân hay gặp?

Thiếu await: test kết thúc trước khi promise xong nên expect bên trong không kịp chạy, hoặc lỗi xảy ra sau khi test đã được tính là qua. Luôn await và dùng expect(...).rejects cho promise bị reject.

Nhớ 3 ý

  1. Vitest tìm file *.test.ts, chạy từng test, báo mong đợi gì và nhận được gì.
  2. Cấu trúc: describe gom nhóm, test là một bài, expect + matcher là khẳng định.
  3. Dùng mock và fake timers để test không phụ thuộc mạng hay giờ thật; coverage chỉ chỉ ra chỗ chưa test.
