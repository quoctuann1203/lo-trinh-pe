INSERT: thêm dòng

INSERT INTO books (title, author, year, price)
VALUES ('Chí Phèo', 'Nam Cao', 1941, 45000)
RETURNING id, created_at;

Luôn liệt kê tên cột. Viết INSERT INTO books VALUES (...) không có tên cột thì câu lệnh phụ thuộc vào thứ tự cột trong bảng, và sẽ hỏng âm thầm khi có người thêm cột mới.

Cột không được nhắc tới sẽ nhận giá trị DEFAULT của nó, hoặc NULL nếu không có default. Ở đây id do identity sinh ra, tags là mảng rỗng, created_at là thời điểm hiện tại.

RETURNING: lấy lại kết quả ngay trong một lệnh

RETURNING là của riêng Postgres. Nó trả về các dòng vừa bị thêm, sửa hoặc xoá, như một câu SELECT. API sách cần trả cuốn sách vừa tạo kèm id, nên đây đúng là thứ bạn sẽ dùng ở tuần 5. Không có nó, bạn phải chạy thêm một câu SELECT, và giữa hai câu có thể có người khác đã sửa dòng đó.

UPDATE: sửa dòng

UPDATE books
SET price = price - 5000, tags = array_append(tags, 'giảm giá')
WHERE id = 3
RETURNING id, title, price, tags;

Chỉ những cột có trong SET bị đổi. Đây đúng là ngữ nghĩa của PATCH ở tuần 1: đổi title thì tags vẫn giữ nguyên.

Nếu WHERE không khớp dòng nào, câu lệnh vẫn chạy thành công và báo UPDATE 0. Code API phải tự kiểm tra con số đó để trả 404.

DELETE: xoá dòng

DELETE FROM books WHERE id = 3 RETURNING title;

Với dữ liệu quan trọng như hoá đơn, sản phẩm thật thường không xoá hẳn mà đánh dấu: thêm cột deleted_at timestamptz và lọc WHERE deleted_at IS NULL khi đọc. Cách này gọi là xoá mềm (soft delete). Tuần này cứ dùng DELETE thật cho bảng sách.

Quên WHERE: lỗi đắt nhất của người mới

UPDATE books SET price = 0;    -- mọi cuốn sách giờ đều miễn phí
DELETE FROM books;             -- bảng trống trơn

Database không hỏi lại. Trên máy mình thì nạp lại file seed là xong, trên database thật thì đó là sự cố. Hai thói quen bảo vệ bạn:

  1. Chạy SELECT trước. Viết SELECT * FROM books WHERE ..., xem đúng các dòng định sửa, rồi mới đổi chữ SELECT * thành UPDATE ... SET hay DELETE, giữ nguyên WHERE.
  2. Bọc trong transaction. Trong psql, mọi thứ giữa BEGIN và COMMIT chưa có hiệu lực thật. Thấy sai thì ROLLBACK.
BEGIN;
UPDATE books SET price = 0;        -- UPDATE 20: ối, cả 20 cuốn
SELECT title, price FROM books;    -- trong transaction này thấy giá 0
ROLLBACK;                          -- huỷ hết
SELECT title, price FROM books;    -- giá cũ đã trở lại

Hôm Thứ Ba, hãy cố ý chạy đúng đoạn này một lần. Cảm giác thấy UPDATE 20 và được cứu bởi ROLLBACK giúp bạn nhớ lâu hơn mọi lời dặn.

UPSERT: thêm hoặc cập nhật

Khi một cột có ràng buộc UNIQUE, bạn có thể nói "thêm mới, nếu đã có thì sửa":

INSERT INTO books (isbn, title, price) VALUES ('978-0132350884', 'Clean Code', 320000)
ON CONFLICT (isbn) DO UPDATE SET price = EXCLUDED.price
RETURNING id, price;

EXCLUDED là dòng bạn vừa định chèn. Bảng sách hôm nay chưa có cột isbn; bạn sẽ thêm nó cùng ràng buộc UNIQUE hôm Thứ Năm, khi đó hãy quay lại chạy thử câu này.

Đừng bao giờ ghép chuỗi để tạo SQL

Ghi chú cho tuần 5, khi code TypeScript gửi SQL:

// Sai: người dùng gửi title là  '); DROP TABLE books; --
await db.query(`INSERT INTO books (title) VALUES ('${title}')`);

// Đúng: giá trị gửi riêng, database không bao giờ coi nó là code SQL
await db.query('INSERT INTO books (title) VALUES ($1)', [title]);

Lỗi ở dòng đầu gọi là SQL injection. Nó vẫn nằm trong nhóm lỗi bảo mật phổ biến nhất, dù cách phòng rất đơn giản: luôn dùng tham số.

Bút đỏ: những câu nghe đúng mà sai

"UPDATE chạy không báo lỗi nghĩa là đã sửa được dòng đó."Chưa chắc. Không khớp dòng nào vẫn là thành công, với UPDATE 0. Phải kiểm tra số dòng bị ảnh hưởng.

"Thêm xong thì SELECT lại theo tên để lấy id."Dùng RETURNING id. Hai sách có thể trùng tên, và giữa hai câu lệnh dữ liệu có thể đã đổi.

"Đã escape dấu nháy rồi thì ghép chuỗi vào SQL vẫn an toàn."Tự escape rất dễ sót. Câu truy vấn có tham số là cách duy nhất nên dùng.

Câu hỏi phỏng vấn

Bạn sẽ làm gì trước khi chạy một câu UPDATE trên database thật?

Chạy câu SELECT với đúng mệnh đề WHERE đó để xem số dòng và nội dung sẽ bị sửa. Chạy UPDATE trong transaction, kiểm tra số dòng bị ảnh hưởng có khớp dự đoán không, rồi mới COMMIT. Nếu sửa nhiều dòng thì chắc chắn có bản sao lưu gần nhất, và tốt nhất là có người thứ hai xem lại câu lệnh.

SQL injection là gì và phòng thế nào?

Là khi dữ liệu người dùng được ghép thẳng vào chuỗi SQL, nên người dùng có thể chèn thêm lệnh SQL của họ, ví dụ đọc bảng khác hay xoá dữ liệu. Phòng bằng câu truy vấn có tham số: câu SQL và giá trị được gửi riêng, database không bao giờ hiểu giá trị là code. ORM và query builder cũng làm như vậy bên dưới.

Xoá mềm và xoá cứng khác nhau thế nào, khi nào dùng cái nào?

Xoá cứng là DELETE thật, dòng biến mất. Xoá mềm là đánh dấu bằng cột như deleted_at và lọc đi khi đọc. Xoá mềm hợp với dữ liệu cần lịch sử hoặc cần khôi phục như hoá đơn, đơn hàng. Đổi lại, mọi truy vấn phải nhớ lọc, và ràng buộc UNIQUE phải tính tới các dòng đã xoá. Với dữ liệu cá nhân mà người dùng yêu cầu xoá, thường phải xoá cứng.
