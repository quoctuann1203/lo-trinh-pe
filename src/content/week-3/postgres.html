Vì sao không lưu vào file JSON hay Map

API sách tuần 1 lưu dữ liệu trong một Map. Tắt server là mất hết. Lưu ra file JSON thì giữ được, nhưng ngay lập tức gặp ba vấn đề:

  • Ghi cùng lúc: hai request cùng đọc file, cùng sửa, cùng ghi lại. Bản ghi sau đè mất thay đổi của bản trước.
  • Hỏng giữa chừng: server sập khi đang ghi nửa file, file JSON hỏng và không đọc lại được.
  • Tìm kiếm: muốn tìm "hoá đơn chưa trả của lớp 3" phải đọc toàn bộ file vào bộ nhớ rồi lọc.

Cơ sở dữ liệu quan hệ giải quyết đúng ba việc đó: cho nhiều người ghi cùng lúc mà không mất dữ liệu, đảm bảo một thay đổi hoặc xong hẳn hoặc không xảy ra (transaction), và tìm kiếm nhanh nhờ index.

Mô hình client và server

PostgreSQL là một chương trình chạy riêng, lắng nghe ở cổng 5432. Ứng dụng của bạn là client: mở kết nối, gửi câu SQL dạng văn bản, nhận lại các dòng kết quả. psql là client dòng lệnh đi kèm Postgres. Tuần 5 bạn sẽ dùng thư viện để code TypeScript làm việc này thay cho psql.

Chạy Postgres bằng Docker Compose

Tạo thư mục sql-practice, trong đó tạo file compose.yaml:

services:
  db:
    image: postgres:18
    environment:
      POSTGRES_USER: hoc
      POSTGRES_PASSWORD: hoc        # chỉ dùng trên máy mình
      POSTGRES_DB: hoc
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql  # dữ liệu sống sót khi tắt container

volumes:
  pgdata:
docker compose up -d                          # chạy nền
docker compose ps                             # cột STATUS phải là "running"
docker compose exec db psql -U hoc -d hoc     # vào psql bên trong container

Từ bản 18, image chính thức lưu dữ liệu dưới /var/lib/postgresql theo từng phiên bản, nên volume gắn vào thư mục đó. Nếu bạn làm theo hướng dẫn cũ gắn vào /var/lib/postgresql/data, container bản 18 sẽ báo lỗi và không chạy.

Vài lệnh psql cần thuộc

Các lệnh bắt đầu bằng dấu gạch chéo ngược là lệnh của psql, không phải SQL, nên không cần dấu chấm phẩy.

LệnhLàm gì
\dtLiệt kê các bảng
\d booksXem cột, kiểu, ràng buộc, index của bảng books
\xBật tắt hiển thị dọc, dễ đọc khi bảng nhiều cột
\timingHiện thời gian chạy mỗi câu lệnh
\qThoát

Câu SQL thì phải kết thúc bằng ;. Nếu quên, psql đổi dấu nhắc từ hoc=# thành hoc-# và chờ bạn gõ tiếp.

Chạy file SQL thay vì gõ tay

Gõ trực tiếp trong psql thì tiện để thử, nhưng bài luyện nên nằm trong file để commit được và chạy lại được. Đưa file vào psql qua đầu vào chuẩn:

docker compose exec -T db psql -U hoc -d hoc -v ON_ERROR_STOP=1 < sql/01-books.sql

-T tắt chế độ terminal để đọc được từ file. ON_ERROR_STOP=1 làm psql dừng ở lỗi đầu tiên thay vì chạy tiếp các lệnh sau như không có gì.

Bảng đầu tiên

-- sql/01-books.sql
DROP TABLE IF EXISTS books;

CREATE TABLE books (
  id         bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  title      text NOT NULL,
  author     text,
  year       integer,
  price      integer NOT NULL,      -- đơn vị: đồng
  tags       text[] NOT NULL DEFAULT '{}',
  created_at timestamptz NOT NULL DEFAULT now()
);

INSERT INTO books (title, author, year, price, tags) VALUES
  ('Dế Mèn phiêu lưu ký', 'Tô Hoài', 1941, 65000, '{thiếu nhi}'),
  ('Số đỏ', 'Vũ Trọng Phụng', 1936, 80000, '{tiểu thuyết}'),
  ('Clean Code', 'Robert C. Martin', 2008, 350000, '{lập trình}'),
  ('Sách chưa rõ tác giả', NULL, NULL, 50000, '{}');
-- Bài luyện: thêm cho đủ 20 cuốn, có vài cuốn author hoặc year là NULL

GENERATED ALWAYS AS IDENTITY là cách chuẩn hiện nay để Postgres tự sinh id tăng dần. Bạn sẽ còn gặp serial trong tài liệu cũ: nó vẫn chạy, nhưng IDENTITY là cú pháp chuẩn SQL và chặn được việc vô tình chèn id bằng tay.

Bút đỏ: những câu nghe đúng mà sai

"Database chỉ là chỗ cất dữ liệu, mọi kiểm tra để code lo."Sai. Database là nơi duy nhất mọi đường ghi dữ liệu đều đi qua. Ràng buộc đặt ở đó thì không bao giờ bị bỏ qua.

"Tắt container là mất dữ liệu."Chỉ khi không có volume. Có volume thì docker compose down vẫn giữ dữ liệu. Muốn xoá thật phải chạy docker compose down -v.

"Mật khẩu trong compose.yaml thì commit lên GitHub cũng được."Chỉ chấp nhận được cho database tập trên máy mình. Database thật thì mật khẩu nằm trong biến môi trường, không bao giờ nằm trong Git.

Câu hỏi phỏng vấn

Vì sao dùng cơ sở dữ liệu quan hệ thay vì lưu file?

Vì database lo ba việc mà tự làm rất khó: cho nhiều client ghi cùng lúc mà không mất dữ liệu, đảm bảo mỗi thay đổi hoặc xong trọn vẹn hoặc không xảy ra kể cả khi server sập, và tìm kiếm nhanh nhờ index. Ngoài ra ràng buộc giữ dữ liệu đúng bất kể code ứng dụng có lỗi.

Postgres khác SQLite thế nào, khi nào dùng cái nào?

SQLite là một thư viện, cả database nằm trong một file và chạy cùng tiến trình với ứng dụng. Nó rất hợp cho app di động, công cụ dòng lệnh, hay web app nhỏ một server. Postgres là server riêng, nhiều ứng dụng kết nối qua mạng, chịu được nhiều người ghi đồng thời và có nhiều tính năng hơn. Với web app có nhiều người dùng như công cụ thu học phí, Postgres là lựa chọn mặc định an toàn.

serial và IDENTITY khác nhau thế nào?

Cả hai đều tạo cột id tự tăng dựa trên một sequence. serial là cú pháp riêng của Postgres, tạo sequence tách rời khỏi cột. GENERATED ALWAYS AS IDENTITY là chuẩn SQL, sequence gắn chặt với cột, và chặn chèn id bằng tay trừ khi bạn nói rõ OVERRIDING SYSTEM VALUE. Bảng mới nên dùng IDENTITY.
