Trong một câu

Promise là một object đại diện cho kết quả sẽ có trong tương lai của một việc phải chờ, như đọc file hay gọi API. async/await là cách viết để chờ promise mà code vẫn đọc từ trên xuống như bình thường.

Hình dung bạn gọi trà sữa và nhận một tờ phiếu có số. Tờ phiếu chưa phải ly trà, nhưng hứa rằng lát nữa bạn sẽ nhận được trà (thành công) hoặc được báo hết hàng (thất bại). Promise chính là tờ phiếu đó; await là đứng chờ gọi số.

Vì sao cần Promise

Ở bài event loop, bạn thấy Node không đứng chờ I/O mà giao việc đi rồi chạy tiếp. Vậy khi việc xong, làm sao code của bạn nhận được kết quả? Ngày xưa Node dùng callback: đưa một hàm cho người ta gọi lại khi xong.

readFile('a.txt', (err, a) => {
  if (err) return handle(err);
  readFile('b.txt', (err, b) => {
    if (err) return handle(err);
    save(a + b, (err) => {
      if (err) return handle(err);
      console.log('xong');
    });
  });
});

Ba bước đã lồng ba tầng, mỗi tầng tự kiểm err, và không dùng được try/catch. Người ta gọi kiểu này là "callback hell". Promise và async/await viết lại đúng việc đó thành:

try {
  const a = await readFile('a.txt', 'utf8');
  const b = await readFile('b.txt', 'utf8');
  await save(a + b);
  console.log('xong');
} catch (err) { handle(err); }

Promise hoạt động thế nào

  1. Tạo: gọi một hàm bất đồng bộ (readFile, fetch) trả về ngay một promise ở trạng thái pending. Việc thật đã bắt đầu chạy ngầm.
  2. Chờ: bạn gắn xử lý bằng .then hoặc await. Luồng JS không đứng chờ, nó đi làm việc khác.
  3. Xong: việc thành công thì promise chuyển sang fulfilled; thất bại thì sang rejected. Chỉ chuyển một lần duy nhất.
  4. Chạy tiếp: event loop cho code sau await (hoặc trong .then) chạy dưới dạng microtask. Nếu rejected, await ném lỗi ngay tại dòng đó.

Ba trạng thái của một Promise

Trạng tháiNghĩa
pendingĐang chờ, chưa có kết quả
fulfilledThành công, có một giá trị
rejectedThất bại, có một lý do (thường là Error)

Promise chỉ chuyển từ pending sang fulfilled hoặc rejected một lần duy nhất rồi giữ nguyên.

function sleep(ms: number): Promise<void> {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

Hàm truyền vào new Promise(...) chạy đồng bộ, ngay lập tức. Trong code thật bạn hiếm khi cần tự tạo, vì hầu hết API đã trả promise sẵn (node:fs/promises, fetch, driver database).

Chuỗi .then, .catch, .finally

Mỗi .then trả về một promise mới. Callback trả giá trị thì giá trị đó được chuyền tiếp. Callback trả promise thì chuỗi chờ promise đó. Callback ném lỗi thì mọi .then sau bị bỏ qua cho đến .catch gần nhất.

const v = await Promise.resolve(1)
  .then((x) => x + 1)                                       // 2
  .then((x) => { throw new Error('ở bước 3: ' + x); })
  .then(() => 'bị bỏ qua')
  .catch((e) => 'catch: ' + e.message)                      // bắt lỗi, chuỗi chạy tiếp
  .finally(() => console.log('finally luôn chạy'));
console.log(v); // "catch: ở bước 3: 2"

async/await

  • async function luôn trả về Promise. return 5 nghĩa là promise fulfilled với giá trị 5.
  • throw trong hàm async nghĩa là promise bị reject. Kể cả lỗi đồng bộ như JSON.parse('{').
  • await p tạm dừng hàm này cho đến khi p xong. Phần code sau await thành một microtask. Luồng JS không bị chặn.
  • Nếu p bị reject, await p ném lỗi ngay tại dòng đó, nên try/catch dùng được.

Làm thử: tuần tự và song song

Chép đoạn dưới vào file time.mts, bọc mỗi cách bằng console.time('tuan-tu') / console.timeEnd('tuan-tu'), chạy node time.mts và so thời gian.

const sleep = (ms: number, v: string) => new Promise<string>((r) => setTimeout(() => r(v), ms));

// Tuần tự: cái sau chờ cái trước. Khoảng 300 ms
for (const x of ['a', 'b', 'c']) await sleep(100, x);

// Song song: cả ba cùng chờ. Khoảng 100 ms
await Promise.all(['a', 'b', 'c'].map((x) => sleep(100, x)));

Tuần tự khi bước sau cần kết quả bước trước. Song song khi các việc độc lập. Với hàng nghìn phần tử, giới hạn mỗi lần 5 đến 10 việc (ví dụ bằng p-limit) để không làm database quá tải.

Khi Promise.all thất bại, các promise còn lại vẫn chạy tiếp. Muốn huỷ thật thì dùng AbortController với API có hỗ trợ, như fetch(url, { signal }).

Bẫy return và return await trong try

const boom = async () => { throw new Error('boom'); };

async function a() {
  try { return boom(); }        // trả promise ra ngoài ngay, catch KHÔNG bắt được
  catch { return 'bắt được'; }
}
async function b() {
  try { return await boom(); }  // chờ ngay trong try, catch bắt được
  catch { return 'bắt được'; }
}

Bút đỏ: những câu nghe đúng mà sai

"arr.forEach(async x => await save(x)) sẽ chờ lưu xong."Sai. forEach không chờ promise. Dùng for...of với await, hoặc await Promise.all(arr.map(save)).

"Thêm async trước hàm là hàm chạy nhanh hơn."Sai. Nó chỉ đổi kiểu trả về thành Promise.

"Promise.all chạy các việc song song."Chính xác hơn: các việc đã bắt đầu từ lúc gọi hàm. Promise.all chỉ chờ chúng cùng lúc.

Tự kiểm tra

Tự trả lời trước, rồi mới bấm mở đáp án.

Hàm async function f() { return 5; }. f() trả về gì?

Một Promise fulfilled với giá trị 5, không phải số 5. Muốn lấy 5 thì await f().

Ba lời gọi API độc lập, mỗi cái 1 giây. Viết await lần lượt mất bao lâu? Dùng Promise.all mất bao lâu?

Lần lượt khoảng 3 giây. Promise.all khoảng 1 giây, vì cả ba cùng chờ.

Gửi nhắc học phí cho 30 phụ huynh, vài người có email sai. Dùng Promise.all hay Promise.allSettled?

allSettled: muốn biết từng người gửi được hay không, không muốn một email sai làm hỏng cả đợt.

Câu hỏi phỏng vấn

Promise là gì? Có mấy trạng thái?

Object đại diện cho kết quả của một việc bất đồng bộ, có ba trạng thái pending, fulfilled, rejected, và chỉ chuyển trạng thái một lần. Gắn xử lý bằng .then/.catch hoặc await.

async/await khác Promise thế nào?

Không phải hai cơ chế khác nhau. async/await là cú pháp xây trên Promise: hàm async trả Promise, await chờ một Promise. Lợi ích là code trông như tuần tự và dùng được try/catch.

Cần gọi 3 API độc lập để dựng trang tổng quan. Bạn viết thế nào?

Gọi song song bằng Promise.all để tổng thời gian bằng cái chậm nhất. Nếu trang vẫn nên hiện khi một API lỗi thì dùng Promise.allSettled và hiện phần có dữ liệu. Đặt timeout cho từng lời gọi.

Đoạn arr.forEach(async x => await save(x)) có vấn đề gì?

forEach không chờ promise: code phía sau chạy trước khi lưu xong, và lỗi của save thành lỗi không ai xử lý, làm process sập. Sửa bằng for...of + await hoặc await Promise.all(arr.map(save)).

Nhớ 3 ý

  1. Promise là lời hứa về kết quả sau này: pending rồi fulfilled hoặc rejected, chỉ một lần.
  2. async/await là cách viết trên Promise: code đọc từ trên xuống, bắt lỗi bằng try/catch.
  3. Việc độc lập thì chạy song song bằng Promise.all; đừng dùng forEach với hàm async.
