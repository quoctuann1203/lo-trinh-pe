Ngôn ngữ và runtime

JavaScript chỉ là ngôn ngữ. Để chạy nó cần một runtime: chương trình đọc code JS, chạy nó, và cho nó công cụ để làm việc với thế giới bên ngoài. Trình duyệt là một runtime, cho JS dùng document, fetch, localStorage. Node là runtime không có document, nhưng có fs để đọc ghi file, http để mở server, process để đọc biến môi trường.

"Một luồng" chính xác là gì

Câu đúng là: code JavaScript của bạn chạy trên một luồng chính, mỗi lúc chỉ một đoạn JS chạy. Nhưng cả process Node có nhiều luồng:

  • Thread pool của libuv, mặc định 4 luồng (đổi bằng UV_THREADPOOL_SIZE). Nó làm việc đọc ghi file, dns.lookup, các hàm crypto nặng như pbkdf2, nén zlib.
  • I/O mạng (nhận request, gọi database) không cần thread pool. Hệ điều hành báo cho libuv khi có dữ liệu (epoll trên Linux, kqueue trên macOS).
  • V8 có thêm luồng riêng để dọn rác và biên dịch.

Chặn và không chặn: quán phở một người phục vụ

Hình dung quán phở chỉ có một người phục vụ (luồng JS). Anh ta nhận order bàn 1, đưa phiếu vào bếp, rồi đi nhận order bàn 2 ngay, không đứng chờ. Bếp nấu xong thì rung chuông, anh ta mang tô ra khi rảnh tay. Nhờ vậy một người phục vụ được cả chục bàn.

Nhưng nếu anh ta tự ngồi băm thịt 5 phút (code tính toán nặng), cả quán phải chờ. Đó là chặn event loop.

import { readFileSync } from 'node:fs';
import { readFile } from 'node:fs/promises';

// Chặn: luồng JS đứng chờ đọc xong. Không request nào khác được xử lý.
const a = readFileSync('big.csv', 'utf8');

// Không chặn: giao việc đọc cho thread pool, luồng JS đi làm việc khác.
// Chỉ hàm này tạm dừng ở await, cả server không dừng.
const b = await readFile('big.csv', 'utf8');

Hệ quả: Node rất hợp với việc chờ I/O (API, gọi database), và kém với việc tính toán nặng (xử lý ảnh, xuất PDF lớn), trừ khi bạn đẩy việc đó sang worker_threads hoặc một hàng đợi công việc riêng.

Concurrency và parallelism

  • Concurrency (đồng thời): nhiều việc cùng đang dở dang và được xen kẽ nhau. Một người phục vụ lo 10 bàn.
  • Parallelism (song song): nhiều việc thật sự chạy cùng một khoảnh khắc trên nhiều nhân CPU. Cần nhiều người phục vụ.

Code JS trong Node có concurrency nhờ event loop. Muốn parallelism cho code JS thì phải dùng worker_threads hoặc chạy nhiều process.

Bút đỏ: những câu nghe đúng mà sai

"async là chạy song song trên luồng khác."Sai. async chỉ là cách viết code chờ kết quả. JS vẫn chạy trên một luồng.

"await làm đứng cả server."Sai. await chỉ tạm dừng hàm chứa nó. Các request khác vẫn chạy.

"Bọc vòng lặp nặng trong async là hết chặn."Sai. Code tính toán vẫn chạy trên luồng chính, dù nằm trong hàm async.

Câu hỏi phỏng vấn

Node.js có phải single-thread không?

Code JS của người dùng chạy trên một luồng chính, nên mỗi lúc chỉ một đoạn JS chạy. Nhưng process Node có thêm thread pool của libuv (mặc định 4 luồng) cho file, DNS, crypto, và các luồng của V8. I/O mạng dùng cơ chế báo sự kiện của hệ điều hành.

Vì sao một luồng mà Node phục vụ được hàng nghìn kết nối?

Vì phần lớn thời gian của một request là chờ I/O, và Node không ngồi chờ. Nó giao việc I/O cho hệ điều hành, đi xử lý request khác, khi có kết quả thì event loop chạy callback tương ứng. Luồng JS chỉ bận trong những khoảng ngắn xử lý dữ liệu.

Một endpoint xuất PDF mất 3 giây CPU. Bạn xử lý thế nào?

Không chạy trên luồng chính, vì trong 3 giây đó mọi request khác phải chờ. Đưa vào hàng đợi công việc, trả 202 Accepted kèm mã công việc, xử lý trong worker riêng. Nếu đơn giản hơn thì dùng worker_threads.

require và import khác nhau thế nào?

require là CommonJS, tải đồng bộ khi chạy tới dòng đó. import là ES module, chuẩn của ngôn ngữ, được phân tích trước khi chạy nên công cụ loại được code thừa, và hỗ trợ await ở cấp cao nhất.
