Trong một câu

Node.js là chương trình chạy JavaScript ngoài trình duyệt, để bạn viết server, công cụ dòng lệnh, script xử lý file bằng chính ngôn ngữ đã quen ở front-end.

Hình dung quán phở chỉ có một người phục vụ. Anh ta không đứng chờ bếp nấu xong mà đi nhận order bàn khác ngay. Node làm việc đúng như vậy: một luồng chạy code JS, nhưng không bao giờ ngồi chờ ổ đĩa hay mạng. Đó là lý do một server Node phục vụ được rất nhiều người cùng lúc.

Vì sao cần Node khi đã có JavaScript

JavaScript chỉ là ngôn ngữ: quy tắc viết const, if, function. Bản thân ngôn ngữ không biết đọc file hay mở cổng mạng. Muốn code chạy được và làm việc với thế giới bên ngoài, cần một runtime.

  • Trình duyệt là một runtime: cho JS dùng document, fetch, localStorage. Nhưng không cho đọc file trên máy, vì lý do an toàn.
  • Node là một runtime khác: không có document, nhưng có fs để đọc ghi file, http để mở server, process để đọc biến môi trường.

Không có Node thì phía server phải viết bằng ngôn ngữ khác (Java, Python, PHP). Có Node, bạn dùng một ngôn ngữ cho cả front-end lẫn back-end.

Từ khoá cần biết

Runtime
Chương trình đọc code JS, chạy nó, và cho nó công cụ làm việc với bên ngoài. Trình duyệt và Node đều là runtime.
V8
Bộ máy chạy JavaScript của Chrome. Node dùng lại V8 để chạy code của bạn.
Luồng (thread)
Một dòng chạy lệnh của CPU. Một luồng làm mỗi lúc một việc.
I/O
Viết tắt của input/output: đọc ghi file, gọi mạng, truy vấn database. Phần lớn thời gian là ngồi chờ thiết bị trả kết quả.
Chặn (blocking)
Luồng JS đứng yên chờ một việc xong mới làm tiếp. Trong lúc đó server không phục vụ được ai.
Event loop
Vòng lặp của Node: hễ có việc I/O xong thì gọi hàm xử lý tương ứng. Có bài riêng ngay sau bài này.
Module
Một file code có thể export hàm cho file khác import.

Node hoạt động thế nào

Bên trong Node có ba mảnh ghép:

MảnhLà gìLàm gì

Khi code của bạn gọi await readFile('big.csv'), chuyện xảy ra theo thứ tự:

  1. V8 chạy code JS tới dòng readFile, gọi xuống API node:fs.
  2. libuv nhận việc và giao cho một luồng phụ trong thread pool đọc file. Luồng JS không chờ.
  3. Luồng JS đi làm việc khác: xử lý request của người dùng khác.
  4. Đọc xong, libuv báo cho event loop. Event loop cho hàm của bạn chạy tiếp từ sau chữ await.

Vì vậy câu "Node chỉ có một luồng" chỉ đúng một nửa. Chính xác là: code JavaScript của bạn chạy trên một luồng chính, mỗi lúc chỉ một đoạn JS chạy. Nhưng cả process Node có nhiều luồng:

  • Thread pool của libuv, mặc định 4 luồng (đổi bằng UV_THREADPOOL_SIZE). Nó làm việc đọc ghi file, dns.lookup, các hàm crypto nặng như pbkdf2, nén zlib.
  • I/O mạng (nhận request, gọi database) không cần thread pool. Hệ điều hành báo cho libuv khi có dữ liệu (epoll trên Linux, kqueue trên macOS).
  • V8 có thêm luồng riêng để dọn rác và biên dịch.

Chặn và không chặn

Quay lại quán phở. Người phục vụ giao phiếu cho bếp rồi đi ngay thì một người lo được chục bàn. Nhưng nếu anh ta tự ngồi băm thịt 5 phút (code tính toán nặng), cả quán phải chờ. Đó là chặn event loop.

import { readFileSync } from 'node:fs';
import { readFile } from 'node:fs/promises';

// Chặn: luồng JS đứng chờ đọc xong. Không request nào khác được xử lý.
const a = readFileSync('big.csv', 'utf8');

// Không chặn: giao việc đọc cho thread pool, luồng JS đi làm việc khác.
// Chỉ hàm này tạm dừng ở await, cả server không dừng.
const b = await readFile('big.csv', 'utf8');

Hệ quả: Node rất hợp với việc chờ I/O (API, gọi database), và kém với việc tính toán nặng (xử lý ảnh, xuất PDF lớn), trừ khi bạn đẩy việc đó sang worker_threads hoặc một hàng đợi công việc riêng.

Concurrency và parallelism

  • Concurrency (đồng thời): nhiều việc cùng đang dở dang và được xen kẽ nhau. Một người phục vụ lo 10 bàn.
  • Parallelism (song song): nhiều việc thật sự chạy cùng một khoảnh khắc trên nhiều nhân CPU. Cần nhiều người phục vụ.

Code JS trong Node có concurrency nhờ event loop. Muốn parallelism cho code JS thì phải dùng worker_threads hoặc chạy nhiều process.

Làm thử: thấy tận mắt việc chặn server

Bước 1. Tạo file block.mjs:

import { createServer } from 'node:http';

createServer((req, res) => {
  if (req.url === '/slow') {
    const end = Date.now() + 5000;
    while (Date.now() < end) {}   // băm thịt 5 giây trên luồng chính
    return res.end('xong việc nặng\n');
  }
  res.end('chào\n');
}).listen(3000, () => console.log('http://localhost:3000'));

Bước 2. Chạy node block.mjs. Mở hai cửa sổ terminal khác.

Bước 3. Ở cửa sổ thứ nhất gõ curl localhost:3000/slow. Ngay sau đó, ở cửa sổ thứ hai gõ curl localhost:3000/.

Kết quả: lệnh thứ hai cũng phải chờ gần 5 giây mới in chào, dù nó chẳng làm gì nặng. Một vòng lặp nặng làm đứng mọi người dùng khác.

Bước 4. Thay vòng while bằng await new Promise((r) => setTimeout(r, 5000)); (nhớ thêm async trước (req, res)) và chạy lại. Lần này curl localhost:3000/ trả lời ngay: chờ bằng hẹn giờ thì không chặn.

Bút đỏ: những câu nghe đúng mà sai

"async là chạy song song trên luồng khác."Sai. async chỉ là cách viết code chờ kết quả. JS vẫn chạy trên một luồng.

"await làm đứng cả server."Sai. await chỉ tạm dừng hàm chứa nó. Các request khác vẫn chạy.

"Bọc vòng lặp nặng trong async là hết chặn."Sai. Code tính toán vẫn chạy trên luồng chính, dù nằm trong hàm async.

Tự kiểm tra

Tự trả lời trước, rồi mới bấm mở đáp án.

Code chạy bằng Node có dùng được document.querySelector không? Vì sao?

Không. document là thứ trình duyệt cho JS dùng, không phải của ngôn ngữ. Node là runtime khác, không có trang web nên không có document.

readFileSync và await readFile cùng đọc một file. Khác nhau ở đâu khi server đang có 100 người dùng?

readFileSync chặn luồng JS, 99 người còn lại phải chờ. await readFile giao việc đọc cho thread pool, luồng JS vẫn phục vụ người khác.

Server Node của bạn xử lý ảnh mất 2 giây CPU mỗi lần. Người dùng khác sẽ thấy gì?

Trong 2 giây đó mọi request khác đều phải chờ. Cần đẩy việc xử lý ảnh sang worker_threads hoặc hàng đợi riêng.

Câu hỏi phỏng vấn

Node.js có phải single-thread không?

Code JS của người dùng chạy trên một luồng chính, nên mỗi lúc chỉ một đoạn JS chạy. Nhưng process Node có thêm thread pool của libuv (mặc định 4 luồng) cho file, DNS, crypto, và các luồng của V8. I/O mạng dùng cơ chế báo sự kiện của hệ điều hành.

Vì sao một luồng mà Node phục vụ được hàng nghìn kết nối?

Vì phần lớn thời gian của một request là chờ I/O, và Node không ngồi chờ. Nó giao việc I/O cho hệ điều hành, đi xử lý request khác, khi có kết quả thì event loop chạy callback tương ứng. Luồng JS chỉ bận trong những khoảng ngắn xử lý dữ liệu.

Một endpoint xuất PDF mất 3 giây CPU. Bạn xử lý thế nào?

Không chạy trên luồng chính, vì trong 3 giây đó mọi request khác phải chờ. Đưa vào hàng đợi công việc, trả 202 Accepted kèm mã công việc, xử lý trong worker riêng. Nếu đơn giản hơn thì dùng worker_threads.

require và import khác nhau thế nào?

require là CommonJS, tải đồng bộ khi chạy tới dòng đó. import là ES module, chuẩn của ngôn ngữ, được phân tích trước khi chạy nên công cụ loại được code thừa, và hỗ trợ await ở cấp cao nhất.

Nhớ 3 ý

  1. Node là runtime chạy JS ngoài trình duyệt: V8 chạy code, libuv lo I/O và event loop.
  2. Code JS chạy trên một luồng, nhưng Node không ngồi chờ I/O, nên một server phục vụ được nhiều người.
  3. Tính toán nặng chặn cả server. Đẩy nó ra worker_threads hoặc hàng đợi riêng.
